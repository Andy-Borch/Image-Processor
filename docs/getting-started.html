Getting Started

Everything you need to build and run Image Processor

Prerequisites

Image Processor uses only the C++ Standard Library and GNU Make, so the dependency list is minimal:

Tool Minimum Version Purpose How to Check
g++ 7.0 (C++11 support) C++ compiler g++ --version
GNU Make 3.81+ Build system make --version
Doxygen 1.8+ (optional) Generate HTML API docs doxygen --version
Valgrind 3.15+ (optional) Performance profiling valgrind --version

Installing dependencies on common platforms

Ubuntu / Debian:

sudo apt update
sudo apt install -y g++ make doxygen valgrind

Fedora / RHEL / CentOS:

sudo dnf install -y gcc-c++ make doxygen valgrind

macOS (Homebrew):

brew install gcc make doxygen valgrind
⚠️ macOS Note The default clang++ on macOS may work, but the project was developed and tested with g++. If you encounter issues, install GCC via Homebrew and prefix with CXX=g++-13.

Installation

Clone the repository from GitHub:

git clone https://github.com/Andy-Borch/Image-Processor.git
cd Image-Processor

The project directory contains all source files at the top level:

Image-Processor/
├── main.cpp
├── Image.h / Image.cpp
├── Pixel.h / Pixel.cpp
├── ColorImage.h / ColorImage.cpp
├── GrayscaleImage.h / GrayscaleImage.cpp
├── BinaryImage.h / BinaryImage.cpp
├── Makefile
├── Doxyfile
├── image1.pgm          ← small test image (2×3)
├── image2.pgm          ← small test image (2×3)
└── large_testimage1.pgm  ← 1920×1080 performance test

Build

Compile the project with a single Make command:

make ImageProcessor

This compiles each .cpp file to an object file (.o) and links them into the ImageProcessor executable. The Makefile uses the following compiler flags:

FlagEffect
-WallEnable all standard compiler warnings
-WerrorTreat every warning as an error
-Wfatal-errorsStop compilation on the first error
-O2Level-2 optimization for faster runtime
✅ Successful build output g++ -Wall -Werror -Wfatal-errors -O2 -o ImageProcessor main.o Image.o ...
The ImageProcessor binary will appear in the project root.

First Run

The program expects exactly two grayscale image files as arguments:

./ImageProcessor <image1.pgm> <image2.pgm>

Try the bundled test images:

# Compare two different small images
./ImageProcessor image1.pgm image2.pgm

# Self-correlation (always outputs 1)
./ImageProcessor image1.pgm image1.pgm

# Large performance test (1920×1080)
./ImageProcessor large_testimage1.pgm large_testimage1.pgm

Expected output for a perfect self-correlation:

1
ℹ️ Output format The program prints the Pearson correlation coefficient to stdout and exits with code 0 on success or -1 on error. Error messages are written to stderr.

Make Targets

TargetCommandDescription
ImageProcessor make ImageProcessor Compile all sources and link the executable
tar make tar Create aborch_ImageProcessor.tar archive of source files
clean make clean Remove executable, object files, and build artifacts

To perform a clean rebuild:

make clean && make ImageProcessor

Generate Doxygen Docs

All source files contain Doxygen-compatible comments. To generate an HTML API reference: 

# Use the provided Doxyfile configuration
doxygen Doxyfile

# Open the generated docs in your browser
open html/index.html       # macOS
xdg-open html/index.html   # Linux
💡 Tip The Doxyfile in the repository root is pre-configured with PROJECT_NAME = "Image Processor". You can customise it further by editing the file or running doxygen -g to regenerate a default configuration.

Troubleshooting

Compilation fails with "command not found: g++"

Install the GCC C++ compiler for your platform (see Prerequisites).

Warning treated as error

The project uses -Werror, so any warning halts the build. This is intentional. Make sure you are using a supported g++ version and have not modified any source files to introduce new warnings.

"Error: Incorrect number of arguments provided"

You must supply exactly two image file paths. Running ./ImageProcessor with no arguments or with one or three arguments will produce this error.

"Error opening image file"

One or both of the provided file paths does not exist or is not readable. Check the path and file permissions.

Executable not found after make

Run make clean then make ImageProcessor again. Confirm that g++ and make are on your PATH.
