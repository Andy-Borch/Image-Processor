File Formats

PBM, PGM, and PPM format specifications as understood by Image Processor

Overview

Image Processor uses the Netpbm family of portable bitmap formats. These are plain-text, ASCII-based formats with a simple structure: a magic-number header followed by pixel values separated by whitespace. They require no external libraries to read or write.

Format Magic Number Extension Channels Value Range Class
PGM — Grayscale P2 .pgm 1 (intensity) 0 – max_value GrayscaleImage
PPM — Color P3 .ppm 3 (R, G, B) 0 – max_value ColorImage
PBM — Binary P1 .pbm 1 (bit) 0 or 1 BinaryImage

PGM — Portable Graymap (P2)

A grayscale image where each pixel is a single integer intensity value. This is the primary format used by Image Processor for the correlation feature.

Structure

P2
<width> <height>
<max_value>
<pixel_1> <pixel_2> ... <pixel_N>

Field Descriptions

FieldTypeDescription
P2stringMagic number — identifies PGM format
widthint > 0Number of pixel columns
heightint > 0Number of pixel rows
max_valueint (typically 255)Maximum legal pixel value; must match actual data
pixel valuesint × (width × height)Row-major, space/newline separated, range 0 – max_value

Example — 2×3 grayscale image

P2
2 3
255
0 15
30 45
60 75

The bundled test file image1.pgm contains exactly this data: a 2-column × 3-row image with intensities 0, 15, 30, 45, 60, 75.

ℹ️ Fast loading GrayscaleImage uses loadImageFast(), which reads the entire file into memory first and then parses it with std::istringstream for improved performance on large files.

PPM — Portable Pixmap (P3)

An RGB color image where each pixel is represented by three consecutive integers (red, green, blue channels).

Structure

P3
<width> <height>
<max_value>
<r1> <g1> <b1>  <r2> <g2> <b2>  ...

Field Descriptions

FieldTypeDescription
P3stringMagic number — identifies PPM format
widthint > 0Number of pixel columns
heightint > 0Number of pixel rows
max_valueint (typically 255)Maximum legal value for any channel
pixel valuesint × (width × height × 3)R, G, B triplets in row-major order

Example — 2×2 color image

P3
2 2
255
255 0 0   0 255 0
0 0 255   128 128 128

Pixel (0,0) = red, (0,1) = green, (1,0) = blue, (1,1) = middle grey.

PBM — Portable Bitmap (P1)

A binary image where each pixel is exactly 0 (black) or 1 (white).

Structure

P1
<width> <height>
1
<pixel_1> <pixel_2> ... <pixel_N>
⚠️ max_value must be exactly 1 Image Processor validates that the max-value header field in a P1 file equals 1. Any other value causes a load error.

Field Descriptions

FieldTypeDescription
P1stringMagic number — identifies PBM format
widthint > 0Number of pixel columns
heightint > 0Number of pixel rows
1int = 1Max value; must be 1 for binary format
pixel values0 or 1 × (width × height)Row-major, whitespace separated

Example — 3×2 binary image

P1
3 2
1
1 0 1
0 1 0

Validation Rules

Every image file is validated by Image::imageFileIsValid() before processing. The following rules must all pass:

#RuleError if violated
1File must be readableError opening image file
2First token must be P1, P2, or P3Unknown input file format
3Width and height must be present and > 0Missing image header information
4Max-value must be present and validMissing image header information
5Total pixel values must equal width × height (× 3 for PPM)Mismatched element count
6Every pixel value must be 0 ≤ v ≤ max_valueInvalid pixel value
7PBM max-value must equal exactly 1Invalid max value for binary image

Conversion Table

The virtual conversion methods allow any image type to be converted to another. The table below shows the formula used for each direction:

From → To Method Formula
RGB → Grayscale ColorImage::convertToGrayscale() I = (R + G + B) / 3
RGB → Binary ColorImage::convertToBinary() B = (R+G+B > 382.5) ? 1 : 0
Grayscale → Binary GrayscaleImage::convertToBinary() B = (I > 127.5) ? 1 : 0
Grayscale → RGB GrayscaleImage::convertToRGB() R = G = B = I
Binary → Grayscale BinaryImage::convertToGrayscale() I = B × 255
Binary → RGB BinaryImage::convertToRGB() R = G = B = B × 255

Checksum Files

The row and column checksum features (Assignments 1 and 2) produce simple text files.

Row checksum file

One integer per line. Line i contains the sum of all pixel intensities in row i (for RGB images, the sum of all three channels for each pixel in the row). 

15       ← sum of row 0
120      ← sum of row 1
230      ← sum of row 2
...

Column checksum file

One integer per line. Line j contains the sum of all pixel intensities in column j. 

90       ← sum of column 0
100      ← sum of column 1
...
ℹ️ Checksum validation Image::providedFilesAreValid() checks that an existing checksum file has exactly the expected number of lines (rows or columns) and that each value is a valid non-negative integer.
