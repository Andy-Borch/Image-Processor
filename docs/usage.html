Usage Guide

Command-line interface, examples, and output interpretation

Synopsis

./ImageProcessor <image1> <image2>

The program accepts exactly two positional arguments — paths to grayscale PGM image files — computes the Pearson correlation coefficient between them, prints it to stdout, and exits.

Arguments

PositionNameTypeDescription
1 image1 file path Path to the first grayscale image (.pgm, P2 format)
2 image2 file path Path to the second grayscale image (.pgm, P2 format)
⚠️ Both images must have identical dimensions The Pearson correlation requires a one-to-one pixel mapping. If the two images have different widths or heights the program exits with an error.

Exit Codes

CodeMeaning
0Success — correlation coefficient printed to stdout
-1 (255)Failure — an error occurred; message printed to stderr

Examples

1 — Compare two small test images

./ImageProcessor image1.pgm image2.pgm

Compares the two bundled 2×3 images. They are related but not identical, so the output will be a coefficient close to (but not exactly) 1.

2 — Self-correlation (perfect correlation)

./ImageProcessor image1.pgm image1.pgm
# Output: 1

Comparing an image with itself always returns 1.

3 — Large image correlation

./ImageProcessor large_testimage1.pgm large_testimage1.pgm
# Output: 1

Tests performance on a full 1920×1080 image (2,073,600 pixels).

4 — Timed performance run

time ./ImageProcessor large_testimage1.pgm large_testimage1.pgm

Use the shell's time builtin to measure execution speed.

5 — Capture output to a file

./ImageProcessor image1.pgm image2.pgm > result.txt
cat result.txt

6 — Suppress error output

./ImageProcessor image1.pgm image2.pgm 2>/dev/null

Understanding the Output

The program outputs a single floating-point number — the Pearson correlation coefficient — which ranges from -1 to 1:

ValueInterpretation
1.0Perfect positive correlation (images are identical or proportionally related)
0.7 – 0.99Strong positive correlation
0.3 – 0.69Moderate positive correlation
0.0No linear correlation
-0.3 – -0.69Moderate negative correlation
-1.0Perfect negative correlation (images are inversely related)

Formula used

The Pearson correlation coefficient r for images X and Y (with n pixels each) is: 

r = Σ (xᵢ - x̄)(yᵢ - ȳ)
    ───────────────────────────────────────
    √[ Σ(xᵢ - x̄)² · Σ(yᵢ - ȳ)² ]

where x̄ and ȳ are the mean pixel intensities of each image. The result is validated to detect NaN (e.g., caused by a constant-value image with zero variance).

Error Reference

Error MessageCauseFix
Error: Incorrect number of arguments provided Program called with <2 or >2 arguments Provide exactly two file paths
Error opening image file File not found or insufficient permissions Verify the path and read permissions
Unknown input file format File does not start with a valid Netpbm magic number Ensure the file is a valid PGM (P2), PPM (P3), or PBM (P1)
Missing image header information Header fields (width, height, max value) are absent or malformed Check the image file header is complete and well-formed
Invalid pixel value A pixel value exceeds the declared max value Ensure all pixel values are within the declared range
Mismatched element count The file contains fewer pixels than width×height requires Verify the image file is not truncated
Images of unequal dimensions cannot be correlated The two images have different width or height Use images with the same dimensions
Correlation result is NaN One or both images has zero variance (all pixels identical) Use images with varying pixel values

Performance Testing

The project was profiled with Valgrind's Callgrind tool. After optimization, a 1920×1080 image correlation requires approximately 3.38 billion instructions (down from 3.48 billion before reference-parameter optimization). 

# Profile with Valgrind Callgrind
valgrind --tool=callgrind ./ImageProcessor large_testimage1.pgm large_testimage1.pgm

# Annotate the profile
callgrind_annotate callgrind.out.<pid>
ℹ️ Key optimization applied getAverageIntensity() was modified to accept a const GrayscaleImage& reference instead of passing by value. This eliminated a full copy of the image data on each call, saving ~100 million instructions on the large test image.

Historical Modes (per Assignment)

The Image::run() method was updated with each course assignment. The table below documents what each version of the program did. To use a historical mode, check out the relevant commit and recompile.

AssignmentBehavior of run()
0Validate image file format and integrity
1Compare provided row/column checksum files against image data
2Generate and write row/column checksums to output files
3Regularize (normalize) image intensities to 0–255
4Convert image between RGB, Grayscale, and Binary formats
5Compute Pearson correlation + generate Doxygen documentation
6Optimized correlation (current build — Valgrind-profiled)
